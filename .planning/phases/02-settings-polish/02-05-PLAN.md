```rust
pub(super) fn flush_pending_persist(hwnd: super::ffi::Hwnd) {
    let snap = with_state_mut(|state| {
        if !state.pending_persist { return None; }
        let mut rect: super::ffi::Rect = unsafe { std::mem::zeroed() };
        unsafe { super::ffi::GetWindowRect(hwnd, &mut rect) };
        state.settings.window.x = rect.left;
        state.settings.window.y = rect.top;
        state.settings.window.w = rect.right - rect.left;
        state.settings.window.h = rect.bottom - rect.top;
        state.pending_persist = false;
        snapshot_for_save(state)
    }).flatten();
    if let Some(snap) = snap { save_settings_if_dirty(snap); }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| settings.json `columns` array → in-memory `column_widths` → painted layout | An attacker who can write the settings file could craft adversarial widths (zero, huge, negative-cast-to-u32). |
| Win32 mouse messages (WM_LBUTTONDOWN/MOVE/UP/SETCURSOR) → drag state machine | The OS delivers these; our code must not deadlock if a callback re-enters during SetCapture/SetCursor. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-22 | Denial of Service | settings.json with `columns: [0, 0, 0, 0, 0, 0, 0]` produces unreadable invisible columns | mitigate | `apply_drag` clamps to ≥40 on the drag path, but a hand-edited settings file bypasses that. Seed path passes values through unchanged; rely on the user's ability to re-drag any column. If a column is invisible, the next save (after any drag elsewhere) preserves the bad column. Accepted residual risk: user can delete settings.json to recover. Documented in plan, not blocking. |
| T-02-23 | Tampering | settings.json with negative values cast to u32 wraps to ~4 billion | mitigate | `Settings.columns` is typed `Vec<u32>` at the JSON layer — the parser already rejects negatives during deserialization. Additionally, `copy_column_widths_to_settings` saturates negative `i32` values to 0 BEFORE the cast for defense-in-depth, tested by `copy_column_widths_clamps_negative_to_zero`. |
| T-02-24 | Tampering | settings.json with a `columns` array of wrong length (2, 0, 99) | mitigate | `seed_column_widths` returns `default_column_widths()` when `len() != fixed_column_count()`. `paint::columns()` also re-applies the same defensive check as a second line of defense. Both paths are unit-tested. |
| T-02-25 | Denial of Service | reentrant lock acquisition via Win32 callback inside `with_state_mut` during SetCapture / SetCursor | mitigate | All Win32 calls (SetCapture, ReleaseCapture, SetCursor, LoadCursorW, InvalidateRect, GetCursorPos, ScreenToClient, DefWindowProcW) are executed OUTSIDE the `with_state_mut` closure per PATTERNS.md §"Save-pattern rule" / §"Mutex reentrancy discipline". Grep-enforced by acceptance criteria. |
| T-02-26 | Tampering | Mouse capture is leaked if SetCapture succeeds but ReleaseCapture is never called (e.g. app crashes mid-drag) | accept | Win32 releases capture automatically when the owning thread exits. Worst case: a crashed drag leaves the mouse captured for that one process instance, which dies with the process. Non-fatal. |
