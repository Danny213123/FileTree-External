## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → settings parser | Hand-edited or corrupted `settings.json` is untrusted input. |
| process → filesystem | Atomic-write window between temp-file write and rename is a small TOCTOU surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Denial of Service | `parse_settings_json` recursive descent | mitigate | Depth counter capped at 64 levels (Pitfall #5); on exceed, return `ParseError::DepthExceeded` without panic. |
| T-02-02 | Tampering | `RawJsonValue::Str` with surrogate-pair content | mitigate | Correct UTF-16 surrogate-pair decoding (Pitfall #6) preserves non-BMP characters round-trip; otherwise an attacker-controlled future-version file could subtly corrupt paths. |
| T-02-03 | Denial of Service | corrupted `settings.json` on load | mitigate | `SettingsStore::load_or_default` falls back to defaults on parse error AND renames the broken file to `settings.json.broken-<ts>` for forensics; never panics. |
| T-02-04 | Tampering | concurrent process writes (out-of-scope this plan) | accept | Phase 2's named-mutex single-instance guard (Plan 02) is the structural mitigation pair per Pitfall #7; in isolation this plan accepts the residual risk because settings.rs is unit-tested in process. |
| T-02-05 | Information Disclosure | `settings.json` containing user paths | accept | AppData ACLs are per-user; documented as containing path lists only (no file contents/hashes/owner data) per RESEARCH §Security. |
| T-02-06 | Tampering | mid-write power loss before MoveFileExW rename | accept | `MOVEFILE_WRITE_THROUGH` is sufficient for personal-use scope per Pitfall #4 + Assumption A2; loss falls back to defaults, non-fatal. |
</threat_model>
