<objective>
Land the single-instance guard and WM_COPYDATA path-forward IPC. On the `desktop`/`gui` code path only, the binary acquires a `Local\FileTree.SingleInstance.v1` named mutex before creating any window; if the mutex already exists, the process finds the primary window, requests foreground rights, forwards the requested scan path via WM_COPYDATA (with a 0x46540001 magic discriminator and a 64 KB cap), then `SetForegroundWindow`s the primary and exits 0. The primary's window proc validates the payload, canonicalizes the path via `GetFullPathNameW`, confirms it exists as a directory, and starts a scan. Invalid payloads are silently dropped.

Purpose: SET-04 + ROADMAP Success Criterion 2 — "Launching a second instance while one is already running focuses the existing window instead of starting a duplicate process." Also pairs with Plan 01's atomic-write recipe to fully mitigate Pitfall #7 (concurrent settings writes).

Output: One-running-instance invariant enforced; second launches feed paths to the primary; integration test validates the contract.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any process on desktop → primary HWND | Any process running in the user's desktop session can `FindWindowW` our class name and `SendMessageW(WM_COPYDATA, ...)`. |
| OS scheduler → foreground rights | `SetForegroundWindow` is restricted by Windows' foreground-rights model; second instance must request rights explicitly. |
| second-instance CLI arg → scan trigger | An attacker who can launch our binary with a chosen `--path` could trigger a scan of an attacker-chosen directory in the primary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Spoofing | `WM_COPYDATA` from arbitrary processes | mitigate | Validate `dwData == FILETREE_PATH_MSG_ID` magic (D-06.2); reject anything else with `return 0`. |
| T-02-08 | Tampering | oversized or malformed `cbData` (DoS via huge alloc) | mitigate | Cap `cbData <= MAX_COPYDATA_BYTES (64 KB)`; reject odd byte counts (must be UTF-16 pairs). |
| T-02-09 | Tampering | path injection (UNC, device path, `..`, non-existent) | mitigate | `GetFullPathNameW` canonicalization + `GetFileAttributesW` directory check (D-06.3); silently drop on validation failure (D-06.4). |
| T-02-10 | Information Disclosure | scan triggered on attacker-chosen path leaks directory metadata via subsequent UI | accept | Personal-use single-user desktop app; attacker controlling the user's session has higher-bandwidth attacks available. Documented as non-goal in RESEARCH §Security TOCTOU row. |
| T-02-11 | Denial of Service | Use-After-Free on `lpData` after `SendMessageW` returns | mitigate | Memcpy out IMMEDIATELY into a local `Vec<u16>` per Pitfall #2; field reads happen before any call that could release the sender. |
| T-02-12 | Elevation of Privilege | foreground-window steal abused for clickjacking | accept | One-shot foreground steal during legitimate second-launch is standard Windows shell behavior; not a new attack surface (RESEARCH §Security). |
| T-02-13 | Denial of Service | mutex held forever by hung primary blocks all relaunches | accept | OS auto-releases the mutex on process death; a hung-but-alive primary is its own UX problem unrelated to single-instance — Task Manager kill is the standard remedy. |
</threat_model>
