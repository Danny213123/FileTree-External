<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| settings file load → window geometry | Persisted x/y/w/h is feed-forward into CreateWindowExW; an attacker who can write the settings file could craft an off-screen window. |
| scan worker thread → status bar update | WM_SCAN_PROGRESS is an existing PostMessageW + Box channel; this plan only consumes its payload. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-18 | Denial of Service | settings.json with off-screen window geometry hides the window | mitigate | `clamp_window_to_workarea` runs BEFORE CreateWindowExW using `SystemParametersInfoW(SPI_GETWORKAREA)`; tested with 4 behavior tests. |
| T-02-19 | Tampering | settings.json with adversarial column widths | accept | Width is `u32`; large values are clamped by Win32 list-view internals; worst case is unreadable columns until user re-drags. Non-fatal. |
| T-02-20 | Denial of Service | settings save fails (disk full) repeatedly mid-mutation storm | mitigate | Drag-coalesce reduces save frequency to one per drag; on failure, debug-only `eprintln!`, release-build swallow per CONTEXT D-03. No modal storm. |
| T-02-21 | Tampering | reentrant lock acquisition via Win32 callback inside `with_state_mut` | mitigate | Snapshot extracted inside closure, save called OUTSIDE the lock per `flush_pending_persist` discipline; pattern enforced by Grep acceptance criterion in task 2. |
