<objective>
Implement two visual refinements that close the Phase 02.1 chrome work per D-03 + D-07 + POL-03:

1. **Owner-draw menu bar** (D-03 scope): Apply MF_OWNERDRAW to every View-menu item and the top-level "&View" menu-bar entry. Implement WM_MEASUREITEM (size each item) and WM_DRAWITEM (paint each item) in `window_proc`. Painted items honor: dark/light palette per state.dark_mode; state.accent_color bg + state.selected_text_color fg on hover/selected; palette_disabled fg on disabled; mnemonic underline only when UISF_HIDEACCEL is clear (POL-03 — Windows-native ALT-to-show behavior). MIM_BACKGROUND via SetMenuInfo recolors the menu-bar gutter (the otherwise white strip between menu items in dark mode).

2. **Custom status footer** (D-07 Apple-HIG restraint): Replace the existing `msctls_statusbar32` child (which can't be reliably dark-themed beyond what apply_theme does today and which carries Windows 95 visual cruft like the sizing grip) with a new custom-painted child window `FileTreeStatusFooter`. Single 22 px logical-px tall row at the bottom of the client area. Reuses the existing `format_status_*` pure helpers from Phase 02 verbatim (no behavior change to status content). Painted with `palette_panel` bg + `palette_text` fg + 1 px `palette_line` top-edge hairline.

Purpose: D-03 + D-07 + POL-03 are the last chrome-polish items in Phase 02.1. Together they remove the remaining "Win9x bones" visible in dark mode — light menu gutters and the chunky status bar with grip.

  WM_UPDATEUISTATE => {
      let action = (wparam & 0xFFFF) as Uint;          // UIS_SET / UIS_CLEAR / UIS_INITIALIZE
      let flags  = ((wparam >> 16) & 0xFFFF) as Uint;  // UISF_HIDEACCEL or UISF_HIDEFOCUS
