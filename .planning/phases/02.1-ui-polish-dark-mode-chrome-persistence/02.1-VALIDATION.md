# Phase 02.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `02.1-RESEARCH.md` § "Validation Architecture" (lines 737–782).

> **Wave 0 / TDD co-location convention (WARNING 5 resolution):** Per the Phase 02 convention adopted by this project, tests are co-located with the production code they exercise — each plan's test additions land in the SAME commit as the production code it covers, gated by `tdd="true"` + `<behavior>` blocks on the relevant tasks (see Plans 02.1-01, 02.1-02, 02.1-03, 02.1-04, 02.1-05 Task 1). Stand-alone Wave 0 scaffolding plans are unnecessary because the production code and its tests never separate in the commit graph; the "Wave 0 Requirements" list below is a reference of which tests each subsequent plan is responsible for landing, not a separate plan slot. The `wave_0_complete: true` frontmatter flag reflects this convention: every test required by the validation matrix is owned by a TDD task inside the plan that creates the production code under test.

## Sampling Rate

- **After every task commit:** Run `cargo test --lib desktop:: settings::`
- **After every plan wave:** Run `cargo test`
- **Before `/gsd-verify-work`:** CI quad green (`cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo build --release && cargo test`) + light/dark screenshot pair committed to `images/`
- **Max feedback latency:** ~5 seconds (quick); ~15 seconds (full)
