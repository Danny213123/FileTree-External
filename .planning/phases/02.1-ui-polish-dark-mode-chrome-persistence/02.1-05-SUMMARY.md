# Phase 02.1 Plan 05: View Menu + Tab Strip Rewire Summary

**One-liner:** View menu bar (3 toggles), 5-tab content-panel strip, WM_INITMENUPOPUP/WM_DWMCOLORIZATIONCOLORCHANGED hooks, Ctrl+1..5 accelerators, and active-tab + drive-picker restore from settings — all wired through a single activate_tab helper with save-outside-lock discipline.

## What Was Built

### Task 1: Pure Foundations (ffi.rs + state.rs)

Three new `isize` menu-item ID constants added to `src/desktop/ffi.rs`:
- `ID_VIEW_SHOW_HIDDEN = 3010`
- `ID_VIEW_SHOW_FILES  = 3011`
- `ID_VIEW_DARK_MODE   = 3012`

`DesktopState` gained a `view_menu: Hmenu` field (initialized to 0 in `DesktopState::new`; populated in `create_controls` for the Pitfall 7 WM_INITMENUPOPUP filter).

New pure free fn in `src/desktop/state.rs`:
```rust
pub(super) fn drive_letter_from_path(path: &str) -> Option<char>
```
Strips `\\?\` prefix, checks `bytes[0].is_ascii_alphabetic() && bytes[1] == b':'`, returns uppercased letter or None. Unit-tested with 9 cases covering C:\, c:/, D:\, \\?\E:\, UNC, empty, POSIX, non-alpha, and degenerate (":").

### Task 2: mod.rs Rewire (9 edits)

**Edit 1 — Toolbar removal:** Deleted 4 `create_child(...BS_AUTOCHECKBOX...)` calls in `create_controls`, the BM_SETCHECK initializer block, and the toolbar layout in `resize_controls`. Fields `hidden_check/files_check/follow_check/dark_check` retained on DesktopState as 0-valued (see Decision 1).

**Edit 2 — View menu construction:** `create_controls` now calls `CreateMenu()` + `CreatePopupMenu()`, appends 3 items with `AppendMenuW`, attaches the submenu via `MF_POPUP`, calls `SetMenu(state.hwnd, main_menu)`, and stores `state.view_menu = view_menu` for the Pitfall 7 guard.

**Edit 3 — Tab strip + 5 panels:** `tabs::register_class(h_instance)` called (idempotent). Tab strip HWND created with `FileTreeTabStrip` class. `tab_panels[0]` aliased to `state.list` if non-zero; panels 1..4 are STATIC placeholder HWNDs with empty text. `apply_dark_mode_to_window` called on each for first-paint flash prevention (D-04).

**Edit 4 — Layout:** `resize_controls` now positions path bar → tab strip (30 px DPI-scaled) → content panels (fill to status bar top). All 5 panels receive the same rect; only the active one is visible. `tabs::recompute_rects` called to update `state.tab_rects`.

**Edit 5 — WM_INITMENUPOPUP arm (line 624):** Pitfall 7 guard `if hmenu == state.view_menu` filters out Shell context menu popups. Inside the guard, `CheckMenuItem` syncs the 3 check states (`show_hidden`, `show_files`, `dark_mode`) with `MF_BYCOMMAND | MF_CHECKED/MF_UNCHECKED`.

**Edit 6 — WM_DWMCOLORIZATIONCOLORCHANGED arm (line 643):** Calls `theme::refresh_accent(state)` + `InvalidateRect(state.tab_strip, null(), 1)` — only the strip surface needs repainting (accent underline lives there).

**Edit 7 — WM_COMMAND arms:** `activate_tab` helper defined at line 1043 (inside `with_state_mut`; never calls `save_settings_if_dirty`). Five `ID_TAB_*` arms and three `ID_VIEW_*` arms all follow the canonical save-outside-lock pattern:
```rust
let snap = with_state_mut(|state| {
    activate_tab(state, ActiveTab::Details);   // or toggle bool for ID_VIEW_*
    state::snapshot_for_save(state)
}).flatten();
if let Some(snap) = snap { state::save_settings_if_dirty(snap); }  // OUTSIDE closure
```
Old `ID_HIDDEN_CHECK`, `ID_FILES_CHECK`, `ID_FOLLOW_CHECK`, `ID_DARK_CHECK` arms deleted.

**Edit 8 — Accelerator table (6 → 11 entries):** Runtime `CreateAcceleratorTableW` array extended with `[MaybeUninit<Accel>; 11]` and `write_unaligned` (required by `#[repr(C, packed(1))]` on the `Accel` struct). Five new entries: `FVIRTKEY | FCONTROL` with keys `VK_1..VK_5` (0x31..0x35) mapped to `ID_TAB_DETAILS..ID_TAB_ERRORS`.

**Edit 9 — Post-ShowWindow restore:** After `ShowWindow + UpdateWindow + start_scan_from_controls`:
- Drive picker restored: reads `state.settings.last_path` inside `with_state_mut`, falls back to `initial_path` when empty, then calls `populate_drive_picker(drive_picker, &path)` with the last-path string (D-11 / POL-01).
- Active tab restored: reads `ActiveTab::from_str(&state.settings.active_tab).unwrap_or(Details)`, computes `restore_tab_id = tab as isize + ID_TAB_DETAILS`, posts `PostMessageW(hwnd, WM_COMMAND, MAKEWPARAM(restore_tab_id as u16, 0), 0)` — routes through the same ID_TAB_* arm as a user click (D-13 / SET-01).

### Implementation Notes Recorded per Plan Output Section

1. **Accelerator path:** Runtime `CreateAcceleratorTableW` with a `[MaybeUninit<Accel>; 11]` array. No `.rc` resource file exists in this project; `LoadAcceleratorsW` was not used.

2. **Toolbar checkbox fields:** Retained on `DesktopState` as 0-valued (never assigned a valid HWND). grep confirms zero consumers in mod.rs post-edit. Comment added near field declarations in state.rs.

3. **Details panel strategy:** `tab_panels[0]` aliased to `state.list` (the existing list HWND) if non-zero at panel-creation time; no re-parenting performed. Both the list and the panel occupy the same client rect — they are the same HWND.

4. **WM_INITMENUPOPUP line:** 624 in the final `src/desktop/mod.rs`.

5. **WM_DWMCOLORIZATIONCOLORCHANGED line:** 643 in the final `src/desktop/mod.rs`.

6. **activate_tab line:** 1043 in the final `src/desktop/mod.rs`.

7. **Save-outside-lock confirmation:** All 5 `ID_TAB_*` arms and all 3 `ID_VIEW_*` arms follow the pattern `let snap = with_state_mut(|state| { ... snapshot_for_save(state) }).flatten(); if let Some(snap) = snap { state::save_settings_if_dirty(snap); }`. The `save_settings_if_dirty` call is at function-body indentation (4-8 spaces), never inside a closure. `activate_tab` itself contains no `save_settings_if_dirty` call. Verified by:
   - `grep -c "fn activate_tab" src/desktop/mod.rs` → 1
   - `awk '/fn activate_tab/,/^}/' src/desktop/mod.rs | grep -c "save_settings_if_dirty"` → 0
   - `grep -c "save_settings_if_dirty" src/desktop/mod.rs` → 13 (8 from ID_TAB_*/ID_VIEW_* arms + existing save calls)
