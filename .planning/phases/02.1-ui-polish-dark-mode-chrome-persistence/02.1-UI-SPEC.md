# Phase 02.1 — UI Design Contract

> Visual and interaction contract for the desktop UI polish phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Surface note:** This is a native Win32 GDI/uxtheme UI, NOT a web app. The conventional shadcn/Tailwind/CSS sections in the upstream template have been mapped to their Win32 equivalents: COLORREF constants instead of CSS variables, `LOGFONTW` + `CreateFontW` instead of font-family stacks, DPI-scaled pixel constants instead of rem units, owner-draw paint routines instead of components, message-loop dispatch instead of CSS pseudo-classes. The 6 quality dimensions (color/typography/spacing/iconography/components-states/interaction) are evaluated against these Win32-native equivalents.

## Spacing Scale (DPI-base, 96 DPI logical pixels)

All values DPI-scaled at use site via `MulDiv(value, GetDpiForWindow(hwnd), 96)`. Multiples of 4 except where Win32-canonical sizes demand otherwise (row height 22 px matches the existing Phase 02 list view; statusbar 22 px matches `msctls_statusbar32`).

| Token | Value | Usage |
|-------|-------|-------|
| `SP_HAIR` | 1 px | Single-pixel hairline dividers (row separators, tab-strip underline thickness, structural seams). Drawn with a 1px `CreatePen(PS_SOLID, 1, color)`. |
| `SP_XS` | 4 px | Icon-to-label gap inside tab headers; vertical padding inside menu items |
| `SP_SM` | 8 px | Tab-header horizontal padding (icon-left, label-right edges); menu-item left padding |
| `SP_MD` | 12 px | Content-area inset from window edge; status-footer pane internal padding |
| `SP_LG` | 16 px | Major section spacing if needed (currently unused by 02.1) |
| `SP_ROW` | 22 px | List-view row height (existing Phase 02 value — preserved verbatim). Dense, lots of data on screen. |
| `SP_STATUS` | 22 px | Custom status-footer total height (matches the `msctls_statusbar32` height it replaces, so layout reflow code from Phase 02 needs zero re-tuning per CONTEXT specifics) |
| `SP_TAB` | 30 px | Content tab strip total height (D-08 specifies 28–32 px; 30 px is the midpoint pick) |
| `SP_ACCENT_UNDERLINE` | 2 px | Accent underline thickness under the active tab |

**Exceptions:** Win32 system controls (system titlebar, native dropdown, accelerator-driven menu popup positioning) use OS-supplied metrics and are not subject to this scale.

## Typography

Two roles total — Win32 desktop convention. No headings; the chrome itself is the hierarchy.

| Role | Face | Size (pt) | Size (px @96DPI) | Weight | Line height | Usage |
|------|------|-----------|------------------|--------|-------------|-------|
| Body | Segoe UI Variable Text | 9 pt | 12 px | FW_NORMAL (400) | derived from font metrics (~16 px row) | All chrome + content text: menu items, tab labels, list-view rows, header, status footer, path bar, drive picker |
| Icon | bootstrap-icons | n/a (size driven in px) | 14 px (tab strip) | FW_NORMAL | matches tab cell | Content-tab header glyphs only (D-02) |

**Weights:** exactly one (FW_NORMAL 400). No bold, no semibold — Apple-HIG-ish restraint per D-07. If a future emphasis ever needs to appear, it must be added to this contract first.

**Sizes:** exactly two roles (Body 9pt, Icon 14 px). Both DPI-scale.

**DPI handling:** Recreate fonts on `WM_DPICHANGED` using `GetDpiForWindow(state.hwnd)`. Cache handles on `DesktopState.fonts { body: Hfont, icon: Hfont }`; `DeleteObject` before replacement.

## Color

Color palette = system accent + tuned grayscale surface (D-05). Light mode keeps current GDI system colors; dark mode uses tuned grayscale fills. Accent is queried from `DwmGetColorizationColor` on launch, cached on `DesktopState.accent_color`, invalidated and re-cached on `WM_DWMCOLORIZATIONCOLORCHANGED`.

### 60 / 30 / 10 split (dark mode)

| Role | Hex | COLORREF (BGR) | Usage |
|------|-----|----------------|-------|
| Dominant 60% — surface | `#1e1e1e` | `0x001E1E1E` | Main window background, content panel background, tab-strip background |
| Secondary 30% — control fill | `#2d2d2d` | `0x002D2D2D` | Menu bar background, status footer background, list-view header fill, popup menu background |
| Accent 10% — system colorization | dynamic (e.g. `#0078D4`) | dynamic | **Reserved for:** active-tab underline (2 px), active-row selection fill in list view, focus ring (if rendered), menu-item highlight, drive-picker focus rectangle |
| Text | `#cccccc` | `0x00CCCCCC` | All body / chrome text in dark mode |
| Hairline | `#3a3a3a` | `0x003A3A3A` | Row dividers, structural seams (path-bar bottom edge, tab-strip bottom edge), menu separators |
| Selected text | `#ffffff` OR `#000000` | dynamic | White on accent fill by default; **switches to `#000000` if accent luminance > 0.6** (light/pale system accents). See "Accent luminance fallback" below. |
| Disabled text | `#7a7a7a` | `0x007A7A7A` | Greyed menu items (e.g. "Cancel" when no scan in flight) |

### Light mode (system-color delegation)

| Role | Source | Notes |
|------|--------|-------|
| Dominant 60% — surface | `GetSysColor(COLOR_WINDOW)` (typically `#FFFFFF`) | Match Win11 light-mode Explorer baseline |
| Secondary 30% — control fill | `GetSysColor(COLOR_3DFACE)` (typically `#F0F0F0`) | Menu / status / header |
| Accent 10% | `DwmGetColorizationColor` (same as dark) | Same reserved-for list |
| Text | `GetSysColor(COLOR_WINDOWTEXT)` (typically `#000000`) | |
| Hairline | `#e5e5e5` | `0x00E5E5E5` — explicit override; do not use 3D etched/sunken styles (D-07) |
| Selected text on accent | `#ffffff` OR `#000000` | Same luminance fallback as dark mode |

### Accent reserved-for list (the 10%, exhaustive)

The accent color appears **only** on these elements. Nowhere else. Any new accent usage must be added to this list first.

1. **Active content-tab underline** — 2 px (`SP_ACCENT_UNDERLINE`) horizontal line beneath the active tab cell only. Inactive tabs have no underline. (D-08)
2. **List-view row selection fill** — full row width, behind text (D-07).
3. **Menu-item hot / highlighted background** — popup menu only, on the currently hot item.
4. **Focus rectangle** on path-bar edit / drive-picker when keyboard-focused (1 px outline using `DrawFocusRect` with the accent COLORREF).

Nothing else uses accent. No accent-colored buttons, no accent-colored icons, no accent text. The treemap and percent bars retain their existing Phase 02 palette (`palette_percent_fill`) — they are data visualization, not chrome.

### Accent luminance fallback

```text
luminance = 0.2126*R + 0.7152*G + 0.0722*B   (R/G/B in 0..1)
if luminance > 0.6  -> selected text = #000000
else                -> selected text = #ffffff
```

Compute once when accent is cached on `DesktopState`. Apply identically in both light and dark mode (the issue is "accent contrast against white text", which is independent of surface color).

### Destructive color

| Role | Hex | Usage |
|------|-----|-------|
| Destructive | (not declared in 02.1) | Out of scope — no destructive actions ship in this phase. Phase 5 (Cleanup) will introduce a `palette_destructive` entry; this contract has no `Delete` / `Move` confirmation UI to color. |

### Content tab strip (D-08) — states

Custom-painted via `WM_PAINT` in the new `tabs.rs` window class. Owner-draw, NOT `SysTabControl32`. Apple-HIG-style: no boxes, no borders, no backgrounds — just icon + label + (active) accent underline.

| State | Visual |
|-------|--------|
| Idle (inactive, not hovered) | Background = `palette_panel(state)` (matches strip bg). Icon + label drawn with `palette_text(state)`. No underline. |
| Hover (mouse over, not active) | Background unchanged. Icon + label color unchanged. Subtle 1 px hairline accent? **No** — keep it dead-quiet, no hover indicator. (Apple-HIG restraint.) Hit-tracking still happens via `WM_MOUSEMOVE` for future use; visual stays still. |
| Active | Background unchanged. Icon + label color unchanged. **2 px accent underline** drawn at the bottom of the tab cell, full cell width. |
| Disabled | Not applicable — all 5 tabs are always enabled in 02.1. |

**Each tab cell:** `[ SP_SM | icon (14 px) | SP_XS | label (9pt) | SP_SM ]`. Tab cell width = `max(SP_SM + 14 + SP_XS + GetTextExtentPoint32W(label).cx + SP_SM, 80 px)` — minimum 80 px for touch comfort and uniformity. Total tab strip height = `SP_TAB` (30 px logical).

**Interaction:** `WM_LBUTTONDOWN` hit-tests the tab rect, computes the clicked tab index, posts `PostMessage(parent, WM_COMMAND, MAKEWPARAM(ID_TAB_DETAILS + index, 0), strip_hwnd)`. Parent's `WM_COMMAND` arm calls the tab-switch helper (see "Interaction & motion").

## Interaction & Motion

**No animations this phase.** Every state change repaints immediately via `InvalidateRect(hwnd, &rc, FALSE)` (no background erase — we own the full paint). The custom-painted surfaces use GDI double-buffering (existing `paint.rs` pattern) so the repaint is flicker-free.

### Tab-switching

1. User clicks a tab cell → `WM_LBUTTONDOWN` in tabs.rs → hit-test → `PostMessage(WM_COMMAND, ID_TAB_<NAME>)`.
2. Parent `window_proc` `WM_COMMAND` arm calls `with_state_mut(|state| state.active_tab = tab_id)`.
3. `tab_switch_handler` calls `ShowWindow(state.tab_panel_<old>, SW_HIDE)`, `ShowWindow(state.tab_panel_<new>, SW_SHOW)`, `InvalidateRect(state.tab_strip, NULL, FALSE)` (to redraw underline).
4. Save settings (discrete event per Phase 02 D-03 — write immediately, no drag-coalesce).

**Keyboard accelerators (per CONTEXT specifics):**

| Accel | Action |
|-------|--------|
| `Ctrl+1` | Jump to Details tab |
| `Ctrl+2` | Jump to Top tab |
| `Ctrl+3` | Jump to Extensions tab |
| `Ctrl+4` | Jump to Duplicates tab |
| `Ctrl+5` | Jump to Errors tab |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | **Deferred** — bonus if trivial, OK to skip (per CONTEXT Deferred) |

The 6 existing Phase 02-03 accelerators (Enter/Esc/Del/Ctrl+F/Ctrl+E/F5) are unchanged. Add the 5 new tab-jump entries to the same `LoadAcceleratorsW` table.

### View-menu toggles

1. User selects `View → ☑ Dark Mode` (or H/F equivalents).
2. `WM_COMMAND` arm calls existing toggle handler (the one previously fired by the deleted toolbar checkbox).
3. Handler flips `settings.<flag>` via `with_state_mut`, calls `apply_theme(state)` (existing), saves immediately.
4. On next `WM_INITMENUPOPUP` for View, checked-state is read fresh from `settings` and `CheckMenuItem` syncs the visual.

### Persistence (D-10..D-13)

| Fix | Mechanism |
|-----|-----------|
| **D-10** First-paint flash | `SetPreferredAppMode(AllowDark)` called in `cli.rs::run_desktop` BEFORE `CreateWindowExW`. `DWMWA_USE_IMMERSIVE_DARK_MODE` set on the main HWND immediately after creation, BEFORE first `ShowWindow`. `SetWindowTheme("DarkMode_Explorer")` called on each child immediately after its `CreateWindowExW` returns. |
| **D-11** Drive-picker restore | After `populate_drive_picker`, parse drive letter from `settings.last_path` (first char if alphabetic, else `'C'`); find matching index in the populated drive list; call `SendMessageW(drive_picker, CB_SETCURSEL, index, 0)`. |
| **D-12** View-menu state sync | `WM_INITMENUPOPUP` arm in `window_proc` for the View menu; reads `settings.show_hidden`, `settings.show_files`, `settings.dark_mode`; calls `CheckMenuItem` for each ID. |
| **D-13** Active-tab persistence | New `settings.active_tab: String` field with default `"details"`. After all child HWNDs are created and shown, route `PostMessage(WM_COMMAND, ID_TAB_<settings.active_tab>)` so the same code path that handles a user click also handles launch restore. Save on tab switch is a **discrete** event (write immediate, no coalesce). |

### Accent color change

`WM_DWMCOLORIZATIONCOLORCHANGED` arm → re-query `DwmGetColorizationColor` → update `DesktopState.accent_color` → recompute luminance + selected-text color → `InvalidateRect(state.hwnd, NULL, TRUE)` to repaint all surfaces.

### DPI change

`WM_DPICHANGED` arm → recreate body + icon fonts at the new DPI → recompute SP_* constants → reflow children using the suggested rect (LPARAM) → `InvalidateRect(state.hwnd, NULL, TRUE)`.

### Uxtheme ordinal fallback

If `GetProcAddress(uxtheme.dll, MAKEINTRESOURCEA(135))` returns null (very old Win10 build or future API removal): dark-mode toggle still flips palette + `DWMWA_USE_IMMERSIVE_DARK_MODE`; system scrollbar and combobox dropdown skin will stay light, but the content area + custom-painted tab strip + owner-draw menu + custom status footer all render correctly. `eprintln!` a one-line debug-only warning. Do not surface a user-visible error.
