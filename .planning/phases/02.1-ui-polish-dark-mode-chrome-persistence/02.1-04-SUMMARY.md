## Deviations from Plan

### Auto-fixed Issues

None — plan executed as written.

**Notable implementation choices:**
- `draw_tab_strip` uses a hardcoded `dpi = 96` because `DesktopState` does not yet have a
  `current_dpi` cache. This is a Rule 2 deviation guard — the function will degrade gracefully
  (correct at 100% scaling) until Plan 02.1-05 adds DPI tracking. Documented here as a known
  limitation, not a bug.
- `MAKEWPARAM` added as `pub(super) fn` in ffi.rs (not a raw FFI binding — it's a Win32
  macro that Rust can implement as a pure function). This is idiomatic.

## Threat Model Compliance

T-02.1-04-01 (WM_PAINT reentrancy deadlock): mitigated via `with_state_mut` → `try_lock`
pattern. If state is locked during WM_PAINT (e.g., from a synchronous Win32 callback), the
paint closure is skipped and the off-screen DC is left unfilled. The `BitBlt` still runs
copying an uninitialized DC — this is visually incorrect but not a crash. Future improvement:
fill with `dark_brush()` when `with_state_mut` returns None. Tracked as deferred item.

T-02.1-04-02 (malformed x-coord from WM_LBUTTONDOWN): `hit_test_tab_index` is pure; returns
None for any out-of-range value. No injection surface.
