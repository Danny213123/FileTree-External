# Phase 02.1: UI Polish — Dark Mode, Chrome, Persistence — Context

**Gathered:** 2026-05-23
**Status:** Ready for planning

<domain>
## Phase Boundary

End-to-end visual cohesion for the desktop UI. After 02.1, FileTree looks consistent in dark and light mode across every Win32 control (menu bar, list-view header, ComboBoxEx32 drive picker, edit, scrollbars, buttons, status bar — none of which currently honor the dark toggle, see `images/Screenshot 2026-05-23 190754.png`), follows an Apple-HIG-style compact aesthetic with Bootstrap Icons glyphs on content-tab headers, replaces the current toolbar row (Hidden / Files / Dark checkboxes) with a TreeSize-style horizontal content-tab strip plus View-menu checkable items, and fixes four known persistence-wiring gaps (dark-mode first-paint flash, drive-picker restore, View-menu state sync, new active-tab persistence).

**In scope:** dark-mode chrome coverage; Bootstrap Icons font embedding; content-tab strip (Details / Top / Extensions / Duplicates / Errors); View-menu migration of existing toggles; compact-density visual refresh; four persistence fixes.

**Out of scope:** new functional features (search, multi-select, cleanup belong to Phases 3–5); auto-follow system dark/light (tri-state); custom non-system titlebar or Mica backdrop; tree-row / menu / status-bar icons; embedded non-system fonts. The ROADMAP.md entry for 02.1 currently has placeholder goal text; the goal should be updated to match this CONTEXT before planning.

<decisions>
## Implementation Decisions

### Icon system

- **D-01:** Icon source = embed `bootstrap-icons.ttf` (TrueType, ~120 KB) under `assets/bootstrap-icons.ttf` via `include_bytes!`, register at startup with `AddFontMemResourceEx`. Render glyphs via `DrawTextW` using Private Use Area codepoints (e.g. `\u{F4A6}` for `bi-list-nested`). Monochrome only (`SetTextColor`); scales perfectly at any DPI; zero decoder code. **GDI does not accept `.woff` / `.woff2`** — the planner must download the `.ttf` build from the Bootstrap Icons releases page on GitHub, not the npm-default `.woff2`. License: MIT (record in NOTICE/about box).
- **D-02:** Icon placement is **content tab headers only** this phase. No tree-row icons, no menu-item icons, no status-bar icons. Apple-style restraint: glyphs appear where they unambiguously add nav value. Other placements deferred (revisit only if monochrome glyphs prove valuable later).

### Dark mode

- **D-03:** Dark-mode strategy = **undocumented Win10/11 uxtheme APIs first, owner-draw only where they fail**. Resolve `uxtheme.dll` ordinal exports via `GetProcAddress` with null-check (graceful no-op on Windows builds that lack them): ordinal **135** `SetPreferredAppMode(AllowDark)`, ordinal **133** `AllowDarkModeForWindow(hwnd, TRUE)`, ordinal **136** `FlushMenuThemes`. Per-control: `SetWindowTheme(hwnd, L"DarkMode_Explorer", NULL)` on the list-view, header, scrollbar parents, ComboBoxEx32, and edit. Owner-draw is required for the menu bar (uxtheme APIs do not cover the standard menu) and `msctls_statusbar32` (its pane backgrounds ignore the dark hint).
- **D-04:** Dark applied **before** `CreateWindowExW` for the main window and all children. Order: read `settings.dark_mode` → call `SetPreferredAppMode(AllowDark|ForceDark)` → create window with `DWMWA_USE_IMMERSIVE_DARK_MODE` set immediately after handle exists (before first `ShowWindow`). Children inherit theme on creation → no first-paint flash.
- **D-05:** Color palette = system accent + tuned grayscale surface. Accent from `DwmGetColorizationColor` on launch and on `WM_DWMCOLORIZATIONCOLORCHANGED`. Surface: dark `#1e1e1e` bg, `#2d2d2d` controls, `#cccccc` text, `#3a3a3a` hairlines; light keeps current GDI sysColors. Selection = accent fill, white text. Not auto-following system theme — explicit `settings.dark_mode` toggle (now exposed via View menu, see D-08).

### Toolbar removal & layout

- **D-06:** Delete the current toolbar row above the list view (the Hidden / Files / Dark checkboxes). Content goes edge-to-edge. The Hidden / Files / Dark toggles move into the **View menu** as `MF_CHECKED` items (`View → ☑ Show Hidden`, `View → ☑ Show Files`, `View → Appearance → ● Light / ● Dark`). Sync checked state via `WM_INITMENUPOPUP` reading current `settings` snapshot.
- **D-07:** Visual target = **Apple-HIG-ish, compact + dense**. Concrete picks (Claude implements):
    - Font: **Segoe UI Variable Text 9pt** (system; no font embed beyond bootstrap-icons.ttf).
    - Row height: **~22 px** (dense, lots of data on screen — matches `images/Screenshot 2026-05-23 190727.png` proportions).
    - Row dividers: **1 px hairline** in `#3a3a3a` (dark) / `#e5e5e5` (light); no zebra striping.
    - Selection: accent fill + white text; no rounded corners on rows; no drop shadows; no elevation.
    - Borders: hairlines only at major structural seams (toolbar/path-bar bottom edge, tab-strip bottom edge). No 3D etched/sunken styles anywhere.

### Content tabs

- **D-08:** TreeSize-style **content tabs** — 5 tabs: **Details / Top / Extensions / Duplicates / Errors**. Layout: path bar → tab strip → content panel → status bar (top-to-bottom). Tab strip is **custom-painted** (owner-draw, not `SysTabControl32` — native tab control is hard to dark-theme cleanly and looks dated), 28–32 px tall. Each tab: bootstrap-icon glyph + label, **accent underline** under active tab, no boxes/borders/backgrounds (Apple style). Single content area swaps on tab change. Owner-draw uses the icon-font codepoints picked by D-01.

### Window chrome

- **D-09:** **Keep the system titlebar.** Native min/max/close, Win11 Snap layouts, Win+arrow shortcuts, accessibility, Aero Shake, edge-resize all work for free. Only behavior is `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE, TRUE)` applied before first `ShowWindow` (see D-04). No `DwmExtendFrameIntoClientArea`, no custom caption buttons, no Mica backdrop this phase.

### Persistence-correctness fixes (all four)

- **D-10:** First-paint flash fix — covered by D-04 ordering.
- **D-11:** **Drive-picker restore.** On launch, after `populate_drive_picker`, parse drive letter from `settings.last_path` and call `CB_SETCURSEL` on the `ComboBoxEx32` to land on the correct drive. Falls back to `C:` if `last_path` is empty / non-Windows-rooted / missing.
- **D-12:** **View-menu state sync.** Handle `WM_INITMENUPOPUP` for the View menu: read `settings.show_hidden`, `settings.show_files`, `settings.dark_mode` and call `CheckMenuItem(..., MF_CHECKED|MF_UNCHECKED)` on each item. Source of truth = `DesktopState.settings`; menu UI is a view, not state.
- **D-13:** **Active tab persistence.** New `settings.json` field `active_tab: "details"|"top"|"extensions"|"duplicates"|"errors"`, default `"details"`. Restored on launch by routing the appropriate tab-switch command after window creation. Save-on-tab-switch is a **discrete** event per Phase 02 D-03 (no drag-coalesce; write immediately). Unknown-keys round-trip from Phase 02 D-02 means older settings.json files load without complaint.

### Claude's Discretion

User opted not to deep-dive these; defaults below. Planner / researcher may revisit if a default proves unworkable.

- **Menu-bar owner-draw scope.** Implement `WM_MEASUREITEM` + `WM_DRAWITEM` for top-level menu items and popup items. Use `GetMenuInfo`/`SetMenuInfo` with `MIM_BACKGROUND` for the menu background brush. Hot/selected colors per palette in D-05. Keep `MF_OWNERDRAW` only for top-level + popup items, not for separators (let GDI draw those with a thin themed pen).
- **Status-bar owner-draw scope.** Replace `msctls_statusbar32` with a simple custom-painted footer (single window, computes 5 panes in `WM_PAINT`, reuses the existing `format_status_*` helpers + pane layout from Phase 02 `paint.rs`). Simpler than owner-drawing the common control with `SBT_OWNERDRAW`.
- **Tab strip implementation.** New `src/desktop/tabs.rs` module: owner-paints the strip, handles `WM_LBUTTONDOWN` → tab switch → `PostMessage(WM_COMMAND, ID_TAB_<NAME>)`. State (`active_tab`) lives on `DesktopState`. Content swap = show/hide one of 5 child container HWNDs (Details = the current list-view; the other 4 are placeholder HWNDs that bind to existing analytics data — full per-tab UI is not in 02.1 scope, only the tab strip + the Details binding + persisted active tab + a "Not yet implemented" placeholder for the other four if those panels don't already exist in the desktop module).
- **Icon-font lookup helper.** New module `src/desktop/icons.rs`: const codepoint constants (`ICON_LIST_NESTED`, `ICON_BAR_CHART`, `ICON_FILES`, `ICON_HDD`, `ICON_EXCLAMATION_TRIANGLE`, etc.) — single source of truth so the rest of the code never hard-codes magic glyphs. A small `draw_icon(hdc, x, y, codepoint, size_px, color)` helper handles font selection + `SetTextColor` + `DrawTextW`.
- **Accent color caching.** Read `DwmGetColorizationColor` once on launch, cache on `DesktopState.accent_color`, invalidate + repaint on `WM_DWMCOLORIZATIONCOLORCHANGED`. Don't query per paint.
- **Fallback for missing uxtheme ordinals.** If `GetProcAddress("uxtheme.dll", 135)` returns null (very old Win10 build or future API removal), dark-mode toggle still flips palette and `DWMWA_USE_IMMERSIVE_DARK_MODE`; just don't get the dark scrollbar/combobox theme — content area + custom-painted tab strip + menu still render correctly. Log via `eprintln!` in debug only.
- **High-DPI.** Already declared per-monitor-aware (Phase 1 setup); icon-font scales for free with `DrawTextW`. Row height + row-height-derived layout constants scale with `GetDpiForWindow` / current dpi snapshot. No special icon-pack-per-DPI work needed (the whole point of the font choice).

</decisions>

### Reusable Assets
- `src/desktop/theme.rs` — already has dark-mode brush globals (`DARK_BRUSH` / `LIGHT_BRUSH`) and `DARK_MODE_ATOMIC`. Extend here for accent + palette + uxtheme resolver; do not introduce a parallel theming module.

- Phase 02-05 column-widths flow (drag → state → settings.columns → atomic write → restore on launch via `paint::columns()` reading state) is the model for `active_tab`. Re-read 02-05-PLAN.md and the `src/desktop/paint.rs::columns` + `state.rs::flush_pending_persist` changes before designing the tab-state plumbing.
- Existing `format_status_*` helpers in `paint.rs` move as-is into the custom-painted footer; only the window class behind them changes.

### Established Patterns
- `unsafe extern "system"` FFI declarations live in `desktop/ffi.rs` (post-Phase-1). Call sites stay in the module that needs the API; the FFI block is declaration-only.
- Win32 constants as `UPPER_SNAKE_CASE` matching the Win32 name (`WM_INITMENUPOPUP`, `MF_CHECKED`, `MIM_BACKGROUND`). Don't anglicize.
- `push_*` builders take `&mut String` first; `*_to_*` serializers; predicates `is_*`/`has_*`/`should_*`.
- `io::Result<T>` propagation up to entry points; `.expect("... lock poisoned")` on Mutex locks.
- GDI double-buffering is the rule for custom-painted surfaces (per `desktop/paint.rs` existing list-view paint); the new tab strip + status footer follow suit to avoid flicker.

### Integration Points
- `cli.rs::run_desktop` — `SetPreferredAppMode(AllowDark)` lands here before `desktop::run`, immediately after `SettingsStore::load_or_default` (so `settings.dark_mode` drives the call).
- `desktop/mod.rs::run` — `DWMWA_USE_IMMERSIVE_DARK_MODE` and `SetWindowTheme("DarkMode_Explorer", NULL)` calls land immediately after the main HWND exists, **before the first `ShowWindow`**. Same for every child created in `create_controls`.
- `desktop/mod.rs::window_proc` — new arms: `WM_INITMENUPOPUP` (menu sync), `WM_DWMCOLORIZATIONCOLORCHANGED` (accent invalidate), `WM_DRAWITEM`/`WM_MEASUREITEM` (menu + tabs + status footer), `WM_COMMAND` with new `ID_TAB_*` and `ID_VIEW_*` IDs.
- Phase 02-03 accelerator table is unchanged; F5 / Ctrl+F / Ctrl+E continue to route to existing handlers — only the entry points (toolbar buttons) for Show Hidden / Show Files / Dark move from buttons to menu items.

<specifics>
## Specific Ideas

- **Bootstrap Icons codepoints** are stable across versions (each glyph has a fixed `bi-*` name → hex codepoint mapping) but versions add/remove glyphs. Pin a specific release in the asset filename (e.g. `bootstrap-icons-1.11.3.ttf`) so an accidental upgrade doesn't silently break a codepoint.
- **Initial tab-strip glyph picks** (override during planning if better fits exist): Details = `bi-list-nested`; Top = `bi-bar-chart`; Extensions = `bi-files`; Duplicates = `bi-copy`; Errors = `bi-exclamation-triangle`.
- **Accent-on-selection contrast.** When the system accent is very light (e.g. user picked white-ish), white text on accent fill becomes unreadable. Compute luminance; if accent luminance > threshold (~0.6), use `#000000` text on selection instead of `#ffffff`. Same fallback in light mode.
- **Menu Alt-key access.** When migrating Hidden/Files/Dark from buttons to View-menu items, give each an `&`-prefix mnemonic (e.g. `&Show Hidden`, `Show &Files`, `&Dark Mode`) so Alt+V then H/F/D works. Match the rest of the menu's mnemonic discipline.
- **Tab keyboard navigation.** Ctrl+Tab / Ctrl+Shift+Tab cycles tabs (deferred unless it's trivial to add). Ctrl+1..Ctrl+5 → jump to tab N. Wire as accelerator entries.
- **Light-mode parity.** Every dark-mode fix must verify light-mode still looks correct — the screenshot pair is the visual reference. Manual QA checkpoint at the end of 02.1 captures a new pair (`images/Screenshot-<date>-light-after.png` / `-dark-after.png`) for diffing.
- **Custom status footer dimensions.** Match the current `msctls_statusbar32` height (≈22 px at 96 DPI) so the existing main-window layout reflow code doesn't need re-tuning.
- **Owner-draw menu hot-key underline.** Honor `WM_UPDATEUISTATE` / `UISF_HIDEACCEL` so mnemonic underscores appear only when Alt is pressed (matches native behavior).

</specifics>
