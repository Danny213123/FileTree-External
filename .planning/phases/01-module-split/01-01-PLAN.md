# Phase Goal

**As a** FileTree maintainer, **I want to** see src/main.rs split into bottom-up extracted top-level modules (model, io, scan, analytics, export, server, cli, diff), **so that** every subsequent feature phase can land in a focused module instead of compounding a 5000-line monolith.

<objective>
Mechanically extract eight top-level modules from `src/main.rs` (5055 lines) in the locked CONTEXT D-05 bottom-up order, one commit per module, with each commit passing the full CI quad (`cargo build && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`). This is the brownfield refactor exception in ROADMAP.md — no behavior changes, no new dependencies, no renames.

Purpose: Maximize `git bisect` granularity per CONTEXT D-03. If a later phase finds a regression introduced by the split, bisect lands on the specific module that broke it.

Output: Eight new module files (`model.rs`, `io.rs`, `scan.rs`, `analytics.rs`, `export.rs`, `server.rs`, `cli.rs`, `diff.rs`) plus a lean ~15-line `src/main.rs`. The `desktop` inline module stays untouched in this plan — it is split in Plan 02.
</objective>
